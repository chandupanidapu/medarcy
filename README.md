# Medarcy: Clinical Intelligence

Medarcy — Premium Clinical Intelligence Platform



Build the final product website and application UI concept



Act as a world-class healthcare SaaS product designer, enterprise UX architect, and senior frontend engineer.



Design and build a highly polished, production-quality web application concept for Medarcy, an advanced Clinical Intelligence Platform for doctors, researchers, and healthcare professionals.



Medarcy is intended to evolve into a highly capable, general-purpose cognitive system, with medicine as its first major domain. Do not claim that it is already Artificial Superintelligence or that it autonomously replaces clinicians. Present it as a sophisticated clinical intelligence platform that supports professional judgment, evidence-based decisions, and human oversight.



The goal is to create a website that looks like a premium, trusted, next-generation medical software product—not a generic AI chatbot, not a hospital management dashboard, and not a marketing landing page.



1. Brand identity



Product name: Medarcy



Primary product descriptor: Clinical Intelligence Platform



Brand personality:



- Premium

- Precise

- Calm

- Intelligent

- Trustworthy

- Clinically professional

- Enterprise-grade

- Modern and futuristic without looking like science fiction



Use a refined medical technology visual identity.



Brand colors



- Deep navy: #16324F

- Dark background: #0B1220

- Secondary dark surface: #111C2E

- Clinical white: #F8FAFC

- Muted slate: #94A3B8

- Gold accent: #C9974A

- Subtle teal accent: #3FA7A0



Use navy and white as the primary brand colors, with gold used sparingly for premium highlights. Teal may be used for clinical status indicators.



Avoid excessive gradients, neon colors, glowing effects, oversized rounded cards, and generic AI visual clichés.



2. Overall visual direction



Create a premium enterprise application inspired by the clarity and usability of modern clinical software, the refinement of high-end productivity tools, and the information density of professional medical workstations.



The interface should feel:



- Clean and spacious

- Information-rich without being crowded

- Fast and focused

- Designed for long clinical work sessions

- Suitable for a doctor using a laptop or desktop

- Fully responsive on tablets and mobile devices



Use a consistent design system:



- Clear typography hierarchy

- Carefully controlled spacing

- Subtle borders

- Soft shadows only where useful

- Consistent iconography

- Accessible contrast

- Smooth but restrained transitions

- Reusable buttons, inputs, panels, badges, and navigation components



Use a professional sans-serif font such as Inter.



3. Main application shell



Build a complete authenticated application interface.



Left sidebar



Create a fixed, elegant sidebar with:



- Medarcy logo and wordmark

- “Clinical Intelligence Platform” subtitle

- New Session button

- Workspace navigation

- Recent sessions

- User profile area



Navigation items:



1. Workspace

2. Clinical Review

3. Medical Research

4. Evidence Engine

5. Drug Intelligence

6. Diagnostics

7. Knowledge Base

8. History



Use minimal, consistent line icons.



The sidebar should be collapsible and responsive. On mobile, convert it into a drawer.



Top header



Include:



- Current workspace or page title

- Global search

- Notifications icon

- Help icon

- User avatar/profile menu



Show a subtle system status indicator such as “Clinical Intelligence Workspace”.



Do not display model provider names such as Claude, Gemini, or OpenAI in the primary product interface.



4. Workspace home screen



Create a premium dashboard that appears when a doctor opens Medarcy.



Welcome section



Use a restrained, professional greeting:



“Good evening, Doctor.”



Below it:



“Your clinical intelligence workspace for patient case analysis, evidence review, medical research, and clinical decision support.”



Use a clean heading and concise supporting text.



Main task composer



Create a large, refined clinical task input panel.



Placeholder:



“Describe a clinical question, enter a case, or choose a task…”



Include:



- Text input area

- Attach file button

- Upload medical document button

- Microphone icon as a visual control

- Submit button



Below the input, show subtle helper text:



“Review clinical information, explore evidence, and generate structured insights.”



Do not make this look like a generic ChatGPT prompt box. It should feel like a professional clinical workbench.



Quick actions



Create six premium task cards:



1. Review a Patient Case

2. Explore Medical Evidence

3. Analyze Laboratory Results

4. Review Medication Safety

5. Research a Clinical Question

6. Generate a Clinical Summary



Each card should have:



- Simple icon

- Subtle hover effect



Recent sessions



Create a compact recent-work section with sample entries:



- Clinical case review

- Evidence review

- Medication safety analysis

- Research question



Use fictional, non-identifiable sample data. Do not use real patient names or actual patient information.



5. Clinical Review workspace



Create a dedicated clinical review experience.



The page should feel like a structured clinical workstation rather than a chat conversation.



Layout



Use a two-column desktop layout:



- Main clinical analysis area

- Right-side context and evidence panel



Case input panel



Include fields for:



- Chief complaint

- History of present illness

- Relevant medical history

- Current medications

- Allergies

- Vital signs

- Laboratory findings

- Examination findings



Use realistic but clearly fictional sample data.



Clinical review result



Show a structured clinical report with sections:



1. Executive Summary

2. Clinical Assessment

3. Clinical Reasoning

4. Differential Diagnosis

5. Recommended Investigations

6. Management Considerations

7. Medication Considerations

8. Follow-up

9. Patient Education

10. Evidence and References

11. Limitations and Uncertainty



Use section navigation or tabs so the report remains easy to scan.



Right-side evidence panel



Include:



- Supporting evidence

- Reference list

- Evidence strength indicator

- Important limitations

- Uncertainty indicators



Clearly distinguish sourced evidence from generated interpretation.



Add a visible notice:



“Clinical decision support only. Verify findings and recommendations before applying them to patient care.”



Include buttons for:



- Save Review

- Export Report

- Regenerate

- Approve Review



Use a confirmation step for approval. Do not imply that the platform independently makes or authorizes clinical decisions.

Create a dedicated research interface with:



- Research question input

Use fictional sample studies and label them as sample content. Do not invent real citations or imply that fictional references are real.

- Open source action



Provide filters for:

Create a medication intelligence page with:



- Medication search

- Indications

- Important warnings

- Monitoring considerations

- References

Create a diagnostics interface with:



- Clinical context input

- Symptom and finding list

- Differential diagnosis panel

- Supporting and opposing findings

- Recommended investigation section

- Uncertainty and limitation indicators



Avoid presenting a diagnosis as certain. Make uncertainty and clinician review visible.



10. Knowledge Base



Create a professional knowledge workspace with:



- Searchable medical knowledge

- Saved references

- Collections

- Recent documents

- Tags

- Source details



Use a clean document-library design.



11. Cognitive intelligence visualization



Include a subtle, professional visualization showing how Medarcy processes a clinical task.



Use a simple horizontal or vertical workflow:



Clinical Context

→ Knowledge Retrieval

→ Reasoning

→ Verification

→ Safety Review

→ Structured Result



This should look like a serious clinical workflow visualization, not a sci-fi brain animation.



Do not claim that the visualization represents actual internal model operations unless the implementation supports it. Present it as a conceptual workflow.



12. Interaction and behavior



Create a working frontend prototype with:



- Functional navigation between pages

- Responsive sidebar

- Search field interactions

- Clickable quick-action cards

- Expandable report sections

- Tabs and filters

- Working modal dialogs

- Clear empty states

- Loading states

- Error states

- Toast feedback for local demo actions



If backend APIs are unavailable, use mock data and clearly treat actions as prototype interactions. Do not pretend to save data to a real database or execute actual clinical analysis.



Keep the components modular and reusable.



13. Responsive design



Desktop:



- Full sidebar

- Wide clinical workspace

- Multi-column report layouts



Tablet:



- Collapsible sidebar

- Reduced panel widths

- Stacked content when necessary



Mobile:



- Drawer navigation

- Single-column layouts

- Readable clinical reports

- Touch-friendly buttons

- No horizontal overflow



14. Technical expectations



Use:



- React

- TypeScript

- Tailwind CSS

- Reusable components

- Lucide icons

- Clean component organization

- Accessible semantic HTML



Use mock data for the visual prototype.



Do not introduce a real backend, authentication system, database, or medical data integration unless specifically requested.



Keep the project easy to connect to a future FastAPI backend.



15. Final quality requirements



The final result must look like a premium, credible, enterprise clinical intelligence product.



Avoid:



- Generic chatbot layouts

- Excessive empty space

- Huge hero headings

- Cartoon medical illustrations

- Neon AI graphics

- Excessive gradients

- Random decorative charts

- Fake real-world clinical citations

- Claims of autonomous diagnosis

- Claims that Medarcy is already ASI



The interface should communicate that Medarcy is a sophisticated clinical intelligence workspace designed to help healthcare professionals analyze information, review evidence, and make better-informed decisions.



Build the complete application prototype with polished page layouts, realistic fictional data, consistent branding, and a cohesive design system.



Prioritize visual quality, clinical usability, and enterprise credibility.
